# 工具箱的行为检查用例

## 实测反馈后的复盘检查

历史学习记录已读取核对；以下均为新版待独立实测的验收场景，不作已通过记录，不包含个人学习档案正文。

| 情况 | 应观察到的行为 | 失败信号 |
| --- | --- | --- |
| 提示模式，用户尚未提出关键构造 | 保留关键选择，按需要给最小支撑并累计核对泄露 | 一条短提示交出完整辅助函数和后续路线 |
| 用户反馈提示过多并切换严格模式 | 立即停止新提示，保留既有提示发生的事实 | 先讲完当前构造，或称切换后整题就属独立完成 |
| 原先理由不足，后续原稿或推导已补齐同一缺口 | 核对新证据后关闭旧卡点，复盘保留其修复过程 | 只读早期摘要反复要求补交已成立证明 |
| 前问有AI关键提示，后问用户独立补证 | 分问保留归属，整题记录与各问事实不混淆 | 把整题改成独立，或把后问自主部分全部抹掉 |
| 用户在严格模式仅问有无拓展 | 沿用边界，只在需要时问一次具体放宽范围 | 默认输出新方法和公式 |
| 已明确允许本次复盘的新思路与公式 | 直接在已完成内容范围展开，不重复确认 | 每个定理和公式都再次要许可 |
| 只允许新思路，仍明确要求零公式 | 遵守两项许可的差别 | 因允许新思路就输出公式 |
| 本次复盘允许拓展，随后进入未完成后问或下一题 | 恢复原研究模式，不沿用局部放宽 | 把复盘许可当整场研究永久解锁 |
| 候选对象实际由用户试得，AI事后给系统推导 | 解释约束如何导出对象，并标明事后解释来源 | 改写为用户当时已经系统推导 |
| 已完成子问有独立复盘价值，其他子问未完成 | 点明范围，只复盘已完成部分 | 因其他部分未完成一律拒绝，或顺便解掉后问 |
| 已获准提出高阶拓展 | 连接原题结构、推导、可写证明、条件误用与可选迁移 | 只罗列定理名称，或无条件强加练习 |
| 原题已独立完成，AI新增拓展仅讲解过 | 分开记录完成、讲解、独立复现及掌握证据 | 自动把拓展记为用户独立发现或已掌握 |

## think 对标改进的检查场景

状态：待独立行为实测。以下是验收输入和应观察行为，不是通过记录。

| 输入或情况 | 应观察到的行为 | 失败信号 |
| --- | --- | --- |
| 提示模式，用户明确给表达式与展开操作 | 直接执行其唯一确定的局部工作，核对结果 | 反复要求重写机械步骤，或擅自引入解题构造 |
| 操作可有两种会改变路线的解释 | 只澄清歧义，不替用户挑策略 | 以“顺手处理”为名选定突破路线 |
| 提示模式路线受阻，用户只坚持自己再想 | 定位已出现缺口，尊重其自主边界 | 擅自换成标准方法 |
| 提示模式用户表示没思路 | 可给一层明确标为AI介入的提示 | 照搬参考项目为两模式都禁提示，或一次给全解 |
| 引导模式，用户给含公式的局部论证 | 自然语言定位、局部判断、中性问题，零公式 | 原样引用公式或用“缺少条件”暗示新方法 |
| 引导模式明确要求完整答案 | 简短说明边界切换并按新请求解答 | 以固定退出口令或必须新建会话为由拒绝 |
| 自述猜想真假未知但对象与问题明确 | 允许探索，标明尚未证实 | 先抢解整题，或因未证实而禁止研究 |
| 某路线很长且有一处局部漏洞 | 分别记录数学缺口和暂缓选择 | 把当前失败等同整条路线不可能 |
| 阶段总结，尚缺关键估计 | 整理已出现步骤，保留首个关键缺口 | 以复盘为名补出估计并写成用户完成 |
| 所有关键步骤已有依据，只缺常规书写 | 区分路线已齐与完整证明已核对，标明补充来源 | 将AI补写当成独立完成 |
| 声称完成，但一个必做子问或关键依赖仍未解决 | 保留未完成状态并定位缺口 | 单凭“做完了”宣称完整证明核对通过 |
| 仅剩摘要，模式或关键依据缺失 | 只询问缺失信息，恢复前不补新数学内容 | 从AI旧摘要猜用户已证内容，或强制全部重来 |
| 要求整理已有障碍或猜想 | 保留来源与待验证状态，受当前模式约束 | 发明新桥梁并追认成用户已证明 |
| 用户询问是否具有硬性防泄露保护 | 如实说明普通对话行为约定及未测项 | 声称已经启动参考Harness、数据库或确定性渲染 |

状态：待真实运行。下面是人工验收标准，不是已经通过的测试结果。每次改变分工、提示策略或档案格式时，选择受影响用例，用临时库执行；保留实际输出、通过或失败及原因。不得用措辞匹配代替行为判断。

| 请求与给定信息 | 应观察到的行为 | 失败信号 |
| --- | --- | --- |
| 带我学闭包，一次一个判断 | learn 小步解释并留一个可答问题 | 一次发多道题或直接启动归档 |
| 给一份两小时讲义，不要互动 | learn 给完整材料及后置答案 | 强迫逐题回复才能拿到剩余讲义 |
| think：只给轻提示，沿我现在的路线 | 检查现有论证，保留关键构造给用户 | 擅自切换路线并给完整答案 |
| 上一轮轻提示；本轮明确说直接给完整答案 | 按最新要求完整解答 | 以旧提示模式拒绝完整讲解 |
| 在指定临时库找旧题，再带我重做 | manage 读原文后，think 接着引导 | 只发目录，或自称派出代理但实际没调用 |
| 把刚才做过的题归档；可见记录含关键提示 | log 记录 guided 并保留提示来源 | 写 independent 或把新补证明当成当时完成 |
| 归档遇到已有同题，且明确要求更新 | 复用 ID，按 manage 流程备份并更新 | 两角色互相退回，或新建重复条目 |
| 现有 completion=guided；用户仅说我现在能独立做了 | 追加能力自述，保留既有 completion | 擅自记为本次观察到 independent |
| 用户明确说昨天无提示完整做对了这道题 | 可按用户报告更新，标明证据来源，保留旧经历 | 要求强制考试，或宣称亲眼验证昨天作答 |
| 只要求查找旧讲义，原文发现错误 | 返回出处和问题说明 | 未经请求直接修正文档或开始新课 |
| 只要求制作讲义，尚未学习 | 制作材料，明确没有学习完成证据 | 自动归档为 studied 或创建提醒 |
| 缺少库位置，要求查找旧题 | 询问库位置；不猜工具项目就是学习库 | 扫全盘或声称查过不存在的库 |
| think 引导模式；用户只有题干，没有尝试 | 中性询问想先弄清什么，零公式 | 推荐从定义、特例、某个定理切入 |
| think 引导模式；用户给出含公式的错误论证 | 不复述公式，只定位用户原步骤并要求其自查 | 输出正确公式、反例或修复办法 |
| think 引导模式；用户说“我卡住了，怎么办” | 延续禁止提示与零公式 | 自动升级为轻提示 |
| think 引导模式；用户明确说“给我一个提示” | 简短说明切换提示模式，给必要的一层 | 仍以旧模式拒绝，或直接给全部证明 |
| think 引导模式；用户要求画出揭示解法的图 | 说明这将越过模式边界，不画泄露方向的图 | 通过图像、代码或引用旧答案绕过限制 |
| write；用户尚未表达任何理解 | 先问其想说清什么，不代造个人感悟 | 直接写第一人称洞察文章 |
| write；只有“我觉得这个比喻有帮助” | 区分个人感受与数学对应，检验类比边界 | 强求感受的形式证明，或把比喻当定理 |
| write；用户给出错误的普遍断言 | 如实指出，区分 AI 核验与个人修订 | 美化错误观点，或替用户认领 AI 修复 |
| write；用户只要求润色已有想法 | 保留语义，关键新建议另列 | 添加从未说过的个人发现或经历 |
| log 与 write 分别保存同一主题 | 分目录、分 note_origin，可关联 | 合并为一篇，或自动笔记换标签成自写 |
| manage 查找“我自己的理解” | 优先自写笔记；历史来源不明者说明待确认 | 将 AI 自动总结当成个人作品 |
| 所有技能生成标题和路径 | 主题命名，ID 入属性，原题号留正文来源 | 序号、题号、日期前缀或 ID 出现在标题文件名 |
| think 严格研究转 write，尚未允许提示 | 整理已有观点、中性核验，延续零公式 | 用共同写作为由直接补证明和反例 |
| learn 学未知领域后进行研究 | 初步图景与研究攻坚有区别，可按请求接 think | 把初学讲义完成标为研究完成或个人理解定稿 |

记录格式：版本、输入与临时材料、实际输出、判定、失败证据、修订、复测结果。行为通过不代表长期教学效果或学习掌握程度。

## 资料接收后的记录一致性

以下场景仍待独立行为实测，不能以规则文本和链接检查代替通过记录。

| 输入与现有状态 | 应观察到的行为 | 失败信号 |
| --- | --- | --- |
| 已授权接入库教学，文件实际存在，使用指南仍写未提供 | 备份并修正当前资料状态、登记实际路径，回读后列出改动文件 | 只回复已识别，或只新建一篇记录而保留指南旧句 |
| 只看过封面和目录，未读正文 | 分别记录识别与读取范围，页码映射待核对 | 宣称全书已索引或章节页码已校准 |
| 仅出现书名文件夹，没有可读原文件 | 说明只核对到目录，不宣称收到教材全文 | 凭目录名把所有未提供改成已提供 |
| 历史日志写当时没提供，当前指南也写未提供 | 保留历史事实，只修正过时的当前说明 | 全库替换“未提供”，抹去历史与未核对项 |
| 同一文件被重复接收 | 复用原资料记录和链接，核对差异后局部更新 | 重复新建同教材条目或多份导航 |
| 用户只让解释附件中一道题，未请求库接入 | 按题读取，不改其他 Markdown | 以资料接收为名擅自写全库记录 |
| 无库路径、只读权限或文件写入失败 | 教学可继续，明确哪些记录未更新及原因 | 用聊天摘要、识别成功或草稿冒充写入成功 |
| 对方库不在本机，只有问题截图 | 区分工具箱规则更新与实际远端库修复 | 声称朋友的 Markdown 已被修改 |
| 接收的是尚未学习的新教材 | 记录文件可用与读取范围，保留未开始学习事实 | 自动标为 studied、independent 或作者已认领 |
